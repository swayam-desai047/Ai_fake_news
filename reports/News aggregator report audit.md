# Audit finds working aggregator, four unmet promises

The AI-Powered News Aggregator (MIT-WPU M.Sc. CS mini project, Group 17) is **substantially but not completely implemented against its synopsis**. Every deterministic part of the system exists and is unit-tested: the 30-minute RSS ingestion, cleaning and exact de-duplication, the eight content dimensions, the Needs Verification flag, TF-IDF cross-source grouping, Supabase storage, the FastAPI endpoints, the Next.js "Daily Signal" dashboard with Recharts analytics, and both server and browser PDF reports. Four synopsis promises are not met: summaries are **extractive, not AI-generated**; **no calibration** was done; **no accuracy, precision, recall or F1 evaluation** exists; and the **frontend reads Supabase directly instead of going through FastAPI**. The BERT-tiny and DistilBERT models are wired in and tested only with fake pipelines; every documented run, including the screenshots recaptured on 25 Nov 2026, used **rules-only mode** because the models are not installed. After the audit, three code bugs were fixed (Al Jazeera source credibility, the 40-character reader-name limit, and the "model" method label on rule-only rows), and the suites now report **backend 63 passed, 3 skipped (opt-in)** and **frontend 32 passed**, with lint and `tsc` clean. The final documentation must follow the college's 11-chapter index exactly, preceded by a title page, four per-student certificates and one group acknowledgement with the placeholder values the team has now fixed. It must also include **two diagrams that do not yet exist: Component and Deployment**.

The code also goes **beyond** the synopsis in ways the final report should present as additions. It has a live-RSS fallback edition scored by rules in TypeScript ([liveNewsService.ts](../frontend/src/lib/liveNewsService.ts), [sections.ts](../frontend/src/lib/sections.ts)) and external news search via Google News RSS, GNews and GDELT ([externalSearch.ts](../frontend/src/lib/externalSearch.ts)). It has name-only reader registration in `named_visitors` ([NameAuthModal.tsx](../frontend/src/components/ui/NameAuthModal.tsx), [profile/route.ts](../frontend/src/app/api/auth/profile/route.ts)), `POST /api/analyze` for custom text and token-protected `POST /api/ingest` ([router.py](../backend/api/router.py)). Further additions are in-memory rate limiting (30/min) and a CORS allow-list ([main.py](../backend/main.py)), RLS hardening and provenance columns ([02_integrity_and_security.sql](../backend/db/02_integrity_and_security.sql)), Python/TypeScript scoring parity tests against [scoring_vectors.json](../shared/scoring_vectors.json), and a re-analysis CLI ([reanalyze.py](../backend/scripts/reanalyze.py)). The synopsis never says how risk is computed. The code defines it: rule weights of 0.35 for source credibility, 0.20 for propaganda and 0.15 each for objectivity, bias and headline accuracy; no score below 65% scoreable weight; labels Low ≤0.35, Moderate ≤0.65, High above ([dimension_service.py](../backend/services/dimension_service.py)).

The biggest practical limit is the input, not the models. RSS excerpts are usually under 150 characters. That is why **all 41 demo articles are flagged Needs Verification**, why most get no summary, and why Headline Accuracy and Content Quality describe the excerpt rather than the article. A sensational headline from an unknown blog scores only Moderate Risk 0.57 because an unscored source credibility dilutes the propaganda penalty ([analyze_example.json](../docs/report/analyze_example.json)). The final report has to discuss both as design limitations.

## Three documents disagree in predictable places

### The synopsis promises more than the code delivers, and its diagrams are conceptual

Most discrepancies between the synopsis and the code come from the four unmet promises above. Several more are differences of method rather than missing work. Source credibility comes from a hand-curated 14-newsroom table with no "source history". Headline accuracy compares the headline with the RSS excerpt, not the article body. Grouping uses the headline counted twice plus the lead sentence, never summaries. Grouping runs once per batch after storage (`update_groups()` in [scheduler.py](../backend/services/scheduler.py)), not per article inside the AI layer.

All five synopsis UML diagrams differ from the code. The **sequence diagram** sends reads through FastAPI; the article page is actually a Next.js server component that reads a cached 500-row Supabase edition ([repository.ts](../frontend/src/lib/repository.ts)). The **class diagram** has Source, Summary and Report entities and attributes that do not exist (`credibilityIndicator`, `generatedAt`, `reportId`, `filePath`, integer ids instead of UUIDs). PDFs are streamed, not stored. The **activity diagram** puts summary and cross-source comparison inside the per-article chain, while the code scores the eight dimensions first, runs the models next and writes the summary last. The **object diagram** contradicts itself: its sentiment of 72 would be labelled positive by the code's ≥60 rule, yet it says "Neutral", and "TechNews Daily" would receive no source score. The synopsis bibliography also omits tools the code uses: the DistilBERT SST-2 model, feedparser, ReportLab, jsPDF, Vitest, the GDELT/GNews/Google News APIs and the Flesch formula ([synopsis PDF](file:///root/.claude/uploads/1906c76c-bbe3-5864-8def-44e8386987c9/7fa5cf3c-synopsiswithdiagram_1.pdf)).

The regenerated diagrams in [docs/report/diagrams/](../docs/report/diagrams/) (from [gen_diagrams.py](../docs/report/gen_diagrams.py)) track the code closely. The **activity** and **use-case** diagrams match. The **object** diagram's values recompute exactly from the formulas: rule risk 1 − 0.847 ≈ 0.15, bias 84 = 90 − 6, content quality 44. Smaller faults remain. The **architecture** diagram's single API → Presentation arrow implies the frontend reads through FastAPI; its "read-only Supabase key" label only half-corrects this, and the live-RSS and external-search paths are missing. The **sequence** diagram shows a by-id select where the code normally uses the cached edition, uses `/api/report` where the frontend calls `/api/v1/report`, and omits the jsPDF path. The **class** diagram draws module-level functions as class methods. The **modules** diagram omits `liveNewsService.ts`, `externalSearch.ts`, `search.ts` and the Next.js API routes.

### The earlier 30-page report is honest but still overstates in four places

The earlier report ([content.html](../docs/report/content.html), rendered as `docs/Project_Report.pdf`) already admits extractive summaries, uncalibrated scores, no P/R/F1 and unexecuted models. Four statements still need correcting. Its conclusion says "every article receives a credibility-risk indicator… and eight explained content scores". In fact the risk score is null ("not assessed") below 65% scoreable weight, and readability, headline accuracy, content quality and unknown-publisher credibility are null for headline-only items. Its scope sentence names only the four backend publishers and leaves out the live-feed and external-search sources. Its feasibility section says the project was "built and tested on a standard laptop-class environment", while its own Table 5.2 says real model inference was not executed. Its test count of **62 passed** is now outdated: the Al Jazeera regression test brings the backend to **63 passed, 3 skipped**.

### Three code bugs found by the audit are now fixed

The audit's code-level findings no longer apply to the current code, and the final report should describe the fixed behaviour. First, the backend stores Al Jazeera as "AlJazeera", which did not match the "al jazeera" reputation key, so those rows received no source credibility. The table now also matches "aljazeera" and those rows score **86** ([dimension_service.py](../backend/services/dimension_service.py), [scoring.ts](../frontend/src/lib/scoring.ts)), with a new regression test. The recaptured analytics page confirms the change: average Source Credibility is now **89** (BBC 93 and Al Jazeera 86 combined), where earlier captures showed 93 from BBC alone ([out_analytics.jpg](../docs/report/img/out_analytics.jpg)). Second, the register modal allowed 60 characters and the route checked only for a non-empty name, while the DB enforces 1–40. Both [NameAuthModal.tsx](../frontend/src/components/ui/NameAuthModal.tsx) and [profile/route.ts](../frontend/src/app/api/auth/profile/route.ts) now enforce 40, so the earlier report's "1–40 characters" claim is true across the whole path. Third, [repository.ts](../frontend/src/lib/repository.ts) tagged every DB row as method "model". Rows with `analysis_method = 'rules'` now show the rule-based ("heuristic") method note.

The fixes leave some dead code and housekeeping items, which do not need reporting as features. The frontend maps `summary_method = 'abstractive'` to an "AI summary" label that the backend never writes. `axios` is declared in [package.json](../frontend/package.json) but never imported. A docstring in [analysis_pipeline.py](../backend/services/analysis_pipeline.py) refers to a non-existent `docs/PROJECT_REPORT.md`.

## Conclusion

The honest headline for the viva is "implemented and unit-tested, demonstrated in rules-only mode". Overclaiming is the bigger risk in this report than any missing code. The gaps are narrow and explainable: no labelled dataset, no model download, and RSS excerpts too short to support summaries or confident scores. The deliverable gains credibility if each synopsis promise is shown as planned → delivered → reason rather than quietly rewritten as achieved. The cheapest improvement before submission is to install the models, run `validate_models.py` and the opt-in tests, and recapture one article screen with `analysis_method = 'model+rules'`. That single step would replace the main weakness, never having executed the transformer models, with real evidence.

On format, the team has resolved every template placeholder and the remaining work is mechanical. The two exceptions need actual work: drawing the Component and Deployment diagrams, and correcting the architecture and sequence diagrams so the read path matches the code. Because the college files say nothing about captions, numbering or citation style, any consistent choice is acceptable. It should still be applied uniformly, with page numbers filled into the Index's empty "Page No." column.
